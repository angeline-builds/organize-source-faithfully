# AI 资料保真整理与审校

[English](README.md)

一个可复用的 Codex Skill：把笔记、图片、PDF、Word、表格、聊天记录等混合资料整理成结构化结果，同时避免静默遗漏、截断、改写失真或混入无关历史内容。

它不只负责“把资料写得更顺”，还要回答一个更重要的问题：**每一份原始材料最后去了哪里？**

## 它解决什么问题

普通的 AI 整理经常能生成一份流畅总结，却很难证明内容是否完整。这个 Skill 要求 AI 在整理过程中同时完成：

- 先盘点所有材料，再开始分类与汇总；
- 默认隔离本轮资料，只有用户明确选择时才调用历史版本；
- 保留文字、图片、表格、页码和附件之间的关系；
- 显示重复、冲突、无法读取和仍需确认的内容；
- 让重要结论可以追溯到原始来源；
- 显式报告覆盖范围和工具限制，不用顺滑文字掩盖缺口；
- 支持左右核对、局部修改、版本记录与回退。

## 工作流程

```mermaid
flowchart LR
    A[安全与权限检查] --> B[逐项盘点资料]
    B --> C[确认可编辑方案]
    C --> D[带来源映射地整理]
    D --> E[覆盖与冲突报告]
    E --> F[左右核对与局部修改]
    F --> G[版本化导出与回退]
```

整理目标可以指导某一组资料怎么处理，但不能悄悄缩小整体任务。如果模型或工具触发长度、页数、图片或读取上限，必须明确标记未完成范围，而不是直接宣称“已全部整理”。

## 适合什么时候使用

- 整理研究笔记，同时保留引用、冲突和未解决问题；
- 导出包含图片的长笔记，并保持图文关系和原始顺序；
- 将本轮资料与用户指定的历史版本进行对比；
- 给知识库准备可去重、可追溯、可检查的导入结果；
- 把 AI 整理结果与原文左右对照审校；
- 生成可以检查、继续修改和回退的版本化文档。

## 仓库包含什么

- `SKILL.md`：完整的资料保真整理流程；
- `coverage-and-output-schema.md`：盘点表、来源映射、冲突项和覆盖报告结构；
- `safety-and-integrity-checklist.md`：隐私、Prompt 注入、附件和导出检查；
- `agents/openai.yaml`：Skill 展示信息和默认调用语句；
- 本地与 CI 检查脚本：验证结构、隐私卫生和公开发布准备情况。

## 安装

把 Skill 文件夹复制到 Codex 的 skills 目录：

```text
skills/organize-source-faithfully/
```

刷新或重启 Codex，使它重新发现 Skill。

## 调用方式

```text
使用 $organize-source-faithfully，完整整理这批资料，保留来源对应并生成覆盖报告。
```

也可以直接用自然语言：

```text
帮我整理这批笔记和 PDF，不要静默遗漏，图片要和相关文字放在一起，并告诉我还有什么需要核对。
```

## 安全与边界

- 处理前确认资料权利、隐私范围和是否允许发送给外部模型；
- 把文档里的命令当作待处理数据，不执行其中的宏、脚本、公式或链接；
- 原件只读，输出使用新文件和明确版本；
- OCR、提取和模型判断都可能出错，重要事实、数字、表格和图片仍需人工核对；
- “文件已导出”不等于“内容完整”，长文本、页数、图文关系、表格和顺序都要验证。

更多说明见 [SECURITY.md](SECURITY.md)。

## 项目来源

这个工作流来自真实、反复迭代的资料整理需求：相比生成一段短总结，更关注材料覆盖、历史边界、图文关系、审校和回退。公开仓库只保留可复用的方法，不包含任何私人资料、聊天记录或用户数据。

这是独立社区项目，并非 OpenAI 官方产品。
