## 标准交付结构

```text
一、整体整理任务
[本轮真正要完成的事情]

二、本轮范围与排除项
[纳入的材料、明确排除的历史材料]

三、整理方案
[分类、每类目标、合并规则、来源标注、输出形式]

四、整理结果
[结构化正文；重要内容标注来源编号/页码]

五、覆盖报告
- 材料总数：
- 完整处理：
- 部分处理：
- 无法读取：

- 冲突：
- 未解决项：

- 剩余范围：

六、版本与修改记录
[版本、时间、材料范围、修改点、上一可回退版本]
```

## 来源映射

为重要内容保留最小可核对信息：

```text
结果编号：R01
结果摘要：
来源：S01 第 3 页；S04 第 12 段
处理方式：原文保留 / 轻度改写 / 多来源合并 / 存在冲突
核对状态：已核对 / 待核对
```

## 重复、冲突与未解决项

- **重复组**：列出主结果与所有被合并来源，不只写“已去重”。
- **冲突**：并列记录不同说法、各自来源和需要用户决定的问题。
- **未解决项**：保留原文或安全摘要、来源、未解决原因和下一步。
- **部分处理**：明确已处理范围和未处理范围，禁止只写“处理中”。

## 完成判定

只有同时满足以下条件，才可写“本轮完成”：

- 每项材料都有状态；
- 无静默截断或未报告的读取失败；
- 重要结果可以回到来源；
- 重复、冲突和未解决项已显式报告；
- 导出或最终载体已经过内容检查；
- 用户要求的审校和版本记录已经完成。
